# Clase 6: El Caso Completo — Proyecto Atlas

## Introducción

La Clase 6 representa la integración de todas las fases estudiadas durante el curso: análisis, requerimientos, elicitación, documentación y diseño.

El objetivo es demostrar cómo estas etapas trabajan juntas para resolver un problema real mediante el desarrollo de un sistema de software.

En este caso, el proyecto utilizado es **Atlas**, una plataforma web educativa diseñada para facilitar el acceso a apuntes, materiales de estudio y contenidos académicos para los estudiantes de la Institución Educativa Javiera Londoño.

> Las cinco fases no son procesos independientes, sino diferentes formas de analizar y resolver un mismo problema.

---

# 1. El Caso de Estudio: Proyecto Atlas

Atlas surge para solucionar la dificultad que tienen muchos estudiantes para mantenerse al día con los contenidos académicos cuando faltan a clases o presentan dificultades de comprensión.

La plataforma permite consultar apuntes, documentos y materiales compartidos por estudiantes y docentes en un entorno digital organizado y accesible.

## Fase 1 — Análisis

Durante la fase de análisis se identificó el problema principal:

- Pérdida de continuidad académica por inasistencia.
- Dependencia de copias físicas.
- Falta de organización de los apuntes.
- Dificultad para acceder a materiales de estudio.

Se decidió desarrollar una plataforma web adaptable a diferentes dispositivos y navegadores para garantizar la accesibilidad de todos los usuarios.

---

## Fase 2 — Requerimientos

Se definieron los requerimientos funcionales y no funcionales necesarios para la plataforma.

### Requerimientos Funcionales (RF)

- RF01: El sistema deberá permitir consultar apuntes organizados por grado y materia.
- RF02: El sistema deberá permitir compartir materiales de estudio.
- RF03: El sistema deberá permitir buscar contenidos académicos.
- RF04: El sistema deberá mostrar los temas vistos durante el periodo escolar.
- RF05: El sistema deberá permitir la visualización de documentos desde cualquier dispositivo.

### Requerimientos No Funcionales (RNF)

- RNF01: La plataforma deberá estar disponible las 24 horas del día.
- RNF02: El tiempo de carga de cada página no deberá superar los 3 segundos.
- RNF03: La interfaz deberá ser adaptable a computadores, tabletas y teléfonos móviles.

---

## Fase 3 — Elicitación

Para comprender las necesidades reales de los usuarios se aplicaron diversas técnicas de recolección de información.

### Entrevistas

Se realizaron entrevistas a:

- Estudiantes.
- Docentes.
- Coordinadores académicos.

Estas entrevistas permitieron identificar dificultades relacionadas con la pérdida de apuntes y la falta de acceso a información actualizada.

### Encuestas

Se aplicaron encuestas para conocer:

- Frecuencia de inasistencia.
- Dificultades para obtener apuntes.
- Interés en una plataforma digital educativa.

### Observación

Se observó el comportamiento cotidiano de los estudiantes.

Durante esta actividad se identificaron problemas como:

- Dependencia de cuadernos físicos.
- Desorganización de materiales.
- Pérdida de información importante.
- Retrasos académicos causados por falta de acceso a contenidos.

---

## Fase 4 — Documentación

La información obtenida fue transformada en documentación formal.

### Casos de Uso Principales

#### Consultar Material Académico

Permite a los estudiantes acceder a apuntes y documentos organizados por materia.

#### Compartir Material de Estudio

Permite publicar documentos, resúmenes o recursos útiles para otros estudiantes.

### Excepciones

- El material solicitado no existe.
- El archivo se encuentra dañado.
- El usuario no posee permisos suficientes para modificar contenido.

---

## Fase 5 — Diseño

Antes de desarrollar el sistema se elaboraron prototipos visuales de la plataforma.

### Wireframes principales

#### Pantalla de Inicio

Permite acceder rápidamente a las materias disponibles.

#### Pantalla de Materias

Muestra los contenidos organizados por asignatura.

#### Pantalla de Materiales

Presenta apuntes, documentos y recursos compartidos.

Posteriormente estos diseños pueden transformarse en prototipos interactivos mediante herramientas como Figma.

# 2. Trabajo en Equipo y Roles

Para el desarrollo del proyecto Atlas se recomienda trabajar en grupos de 3 a 5 integrantes.

## Analista

Responsable de:

- Entrevistas.
- Encuestas.
- Identificación de necesidades.

## Diseñador

Responsable de:

- Wireframes.
- Experiencia de usuario.
- Diseño visual.

## Documentador

Responsable de:

- Elaboración del SRS.
- Casos de uso.
- Requerimientos.

## Presentador

Responsable de:

- Sustentación final.
- Demostración del proyecto.

# 3. Documento SRS Comprimido

El proyecto Atlas debe incluir una versión resumida del estándar IEEE 830.

## Introducción

- Propósito del sistema.
- Alcance.
- Usuarios objetivo.

## Requisitos

### Funcionales

Mínimo 5 requerimientos funcionales.

### No Funcionales

Mínimo 3 requerimientos no funcionales medibles.

## Casos de Uso

Al menos dos casos de uso completos con excepciones.

## Wireframes

Mínimo tres pantallas representativas del flujo principal.

# 4. Sustentación de 5 Minutos

La presentación final debe seguir una estructura organizada.

## El Gancho (30 segundos)

Pregunta inicial:

> ¿Qué ocurre cuando un estudiante falta varios días y no consigue apuntes completos?

---

## El Problema (1 minuto)

Explicar:

- Retrasos académicos.
- Dependencia de copias.
- Desorganización de información.

---

## La Solución (1 minuto)

Presentar Atlas y sus principales funcionalidades:

- Consulta de apuntes.
- Organización por materias.
- Compartición de materiales.
- Acceso desde cualquier dispositivo.

---

## La Demo (1 minuto y 30 segundos)

Mostrar:

- Navegación principal.
- Consulta de contenidos.
- Organización de materiales.

---

## El Cierre (1 minuto)

Explicar:

- Aprendizajes obtenidos.
- Beneficios para la comunidad educativa.
- Posibles mejoras futuras.

---

# 5. Ideas Clave para el Éxito

- El software debe planificarse antes de desarrollarse.
- Las decisiones deben basarse en evidencias obtenidas durante la elicitación.
- Los requerimientos deben ser claros y medibles.
- Los casos de uso deben incluir excepciones.
- El diseño debe enfocarse en las necesidades reales de los estudiantes.
- Atlas busca mejorar el acceso a la información académica y promover el aprendizaje colaborativo.

---

# Resumen Principal

- Atlas es una plataforma educativa diseñada para facilitar el acceso a apuntes y materiales escolares.
- El proyecto integra análisis, requerimientos, elicitación, documentación y diseño.
- Se identifican necesidades reales mediante entrevistas, encuestas y observación.
- Los requerimientos se documentan mediante un SRS.
- El diseño se representa mediante wireframes y prototipos.
- La sustentación debe comunicar claramente el problema, la solución y los beneficios del sistema.
